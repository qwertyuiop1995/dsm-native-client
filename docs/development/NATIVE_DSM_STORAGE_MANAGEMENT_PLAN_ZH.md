# “统一存储管理”新功能三端实现计划

> **功能来源：**“统一存储管理”是岚仓新增的组合功能，由群晖“存储管理器”和“存储空间分析器”两个官方组件的能力合并而成，不是群晖原有的单一套件，也不改变两个官方组件在 NAS 上的安装与运行方式。
>
> 当前完成情况和验证结果以[当前开发进度](../progress/STATUS.md)为准。本文只维护产品边界、契约、实施顺序和验收条件。

## 目标

把群晖“存储管理器”和“存储空间分析器”的用户任务合并，形成一个新的原生“统一存储管理”入口：

- 总览：容量、可用空间、整体健康、卷使用趋势。
- 空间分析：共享文件夹、文件类型、所有者、大文件、最近修改、最久未访问和重复内容。
- 存储池与硬盘：卷、存储池、RAID、硬盘状态、温度与 S.M.A.R.T. 检测。

界面合并不改变底层安全边界。硬盘检测仍按危险写操作处理；空间分析默认只读，必须由用户主动开始并可随时停止。

## 契约边界

| 范围 | 契约 | 边界 |
| --- | --- | --- |
| 卷、存储池、硬盘 | `SYNO.Storage.CGI.Storage`、`SYNO.Core.Storage.Disk` 内部接口 | 仅在能力发现返回兼容版本时启用；写操作必须确认、防重复并回读 |
| 文件枚举与属性 | `SYNO.FileStation.List`、`SYNO.FileStation.Search` 官方 API | 只分析当前账号可见内容；回收站、远程挂载、套件数据和快照不计入 |
| 重复内容 | `SYNO.FileStation.MD5` 官方 API | 先按文件大小筛选候选，再逐个校验内容；取消时停止后台任务 |
| 历史报告 | Storage Analyzer 套件内部契约尚未固化 | 当前不读取或修改套件报告配置，不猜测未公开接口 |

逻辑文件大小与文件系统实际占用可能因快照、稀疏文件、压缩和去重而不同，界面必须使用“文件占用”而不是“可释放空间”描述扫描汇总。

## 三端实施顺序

| 阶段 | Apple 平台 | Android | Windows |
| --- | --- | --- | --- |
| S1 统一只读总览 | 共享 Swift 领域模型；macOS 与移动端分别使用原生自适应导航 | Kotlin 领域模型与 Compose 页面 | C# 领域模型与 WinUI 页面 |
| S2 用户主动空间分析 | 使用共享业务规则；移动端支持后台执行与系统取消 | 使用协程、前台服务和系统通知 | 使用后台任务和系统进度 |
| S3 硬盘检测 | 保持确认、防重复和结果复查；移动端采用适合小屏的流程 | 保持同一安全门槛 | 保持同一安全门槛 |
| S4 套件历史报告 | 取得脱敏、版本化契约后再实现只读导入 | 复用共同 Schema | 复用共同 Schema |
| S5 报告配置与计划 | 必须先完成权限、幂等、取消和写后复查设计 | 保持同一安全门槛 | 保持同一安全门槛 |

## 原生体验要求

- macOS 使用 SwiftUI、Swift Charts、系统表格和系统窗口行为。
- iPhone/iPad 使用触控友好的分层导航、动态文字和 VoiceOver。
- Android 使用 Jetpack Compose、Material 语义和预测性返回。
- Windows 使用 WinUI、键盘导航和屏幕阅读器语义。
- 所有平台提供深浅色模式、降低动态效果、可访问数值说明和图表之外的列表表达。

## 验收清单

- 套件未安装、停用、升级中、无管理员权限和接口缺失时均有可恢复提示。
- 1 千、1 万和 10 万文件场景验证内存、取消、休眠唤醒和网络中断。
- 多卷、多共享、只读共享、加密未挂载共享、远程挂载和回收站分别验证。
- 重复内容验证同名不同内容、不同名相同内容、零字节文件、大文件取消和校验接口不可用。
- 所有兼容记录只写版本与结论，不记录真实路径、文件名、所有者或校验值。
