# DSM 与套件私有 API 发现规范

本目录保存按 DSM build 和套件版本归档的私有 API 发现证据。目标是让系统或套件升级后的兼容复验能够回答以下问题：

- 哪个版本实际观察到了哪个接口和字段。
- 观察来自能力发现、网页请求、脱敏响应还是行为验证。
- 新旧版本之间增加、变化或移除了什么。
- 客户端应继续启用、降级、关闭还是等待专用环境验证。

这里记录的是版本化发现证据，不替代 [`DSM_COMPATIBILITY_MATRIX.md`](../../compatibility/DSM_COMPATIBILITY_MATRIX.md) 中面向产品能力的兼容结论。

## 目录

```text
environments/       DSM、套件和验证条件的脱敏快照
endpoints/          单个 API 或紧密关联 API 组的稳定记录
upgrade-reports/    DSM 或套件升级前后的差异与处置报告
```

机器可读索引位于 [`contracts/private-api/compatibility.json`](../../../contracts/private-api/compatibility.json)。文档和索引必须在同一次变更中更新。

当前人工阅读入口：

- [匿名环境与版本基线索引](environments/INDEX.md)
- [当前私有 API 端点组索引](endpoints/INDEX.md)

## 发现原则

1. 优先使用 Synology 官方公开 API。私有 API 仅在公开 API 无法满足必要能力时发现和接入。
2. 发现阶段默认只读。不得为了确认接口而创建、修改、删除、启动、停止、安装、卸载、重启、关机或改变网络与权限。
3. 写接口只能在专用测试环境、明确授权和可恢复条件下验证，并具备权限检查、用户确认、重复提交保护和写后回读。
4. 可以利用已登录的 DSM 网页会话观察官方页面产生的请求，但不得导出或提交原始 HAR、Cookie、SID、SynoToken、DID 或未脱敏响应。
5. 只保存理解契约所需的最小字段。用户名、NAS 地址、IP、QuickConnect ID、共享名、路径、文件名、聊天内容、日志正文、容器环境变量等一律替换为语义占位值。
6. 翻译后的页面文字、压缩混淆后的前端变量名和偶然请求顺序不能作为稳定业务契约。

## 多台 NAS 与多版本标识

- 每台用于发现的 NAS 分配匿名稳定别名：`lab-a`、`lab-b`、`lab-c`，不得使用设备名、型号、序列号、地址、账号或 QuickConnect ID。
- 同一台 NAS 升级后继续使用原别名，但为新的 DSM/套件组合新建环境 ID。
- 环境 ID 使用 `<设备别名>-dsm-<版本>-<build>-<update>-<日期>` 的可读形式，例如 `lab-a-dsm-7-2-1-69057-u12-20260729`。
- 每个匿名设备最多有一个 `current` 基线；升级后旧基线改为 `historical`，新基线使用 `supersedes` 指向旧基线。
- 同一 API 的稳定说明只维护一份；不同环境的版本和证据作为 verification 追加，避免复制出互相漂移的接口说明。
- 人工阅读从 [`environments/INDEX.md`](environments/INDEX.md) 开始，机器和 AI 从 `contracts/private-api/compatibility.json` 开始。

## 每次发现的必备记录

开始发现前，复制 [`environments/TEMPLATE.md`](environments/TEMPLATE.md) 建立环境快照，至少记录：

- DSM 版本、build 与 Update 编号。
- 相关套件名称、内部标识和完整版本。
- 发现日期、连接方式类别、账号权限类别和证书类别。
- 浏览器页面、`SYNO.API.Info`、脱敏请求结构或测试结果等证据来源。
- 未知项和无法在当前设备验证的限制。

每个私有接口复制 [`endpoints/TEMPLATE.md`](endpoints/TEMPLATE.md)，至少记录：

- API 名称、路径、HTTP 方法、接口版本和所属 DSM/套件。
- 公开或内部分类、读写性质、权限与副作用。
- 请求参数和响应结构，不记录真实值。
- 首次观察、最后验证和已覆盖环境。
- 能力探测条件、失败语义、降级策略和功能开关。
- 自动化测试、脱敏 fixture 及客户端 Adapter 的位置。

“在前端代码中找到字符串”只能记为“静态发现”；“浏览器中观察到请求”只能记为“已观察”；读取真实脱敏响应后可记为“只读验证”；写入并完成最终状态复查后才可记为“行为验证”。

## 证据等级

| 等级 | 含义 | 可以得出的结论 |
| --- | --- | --- |
| `static` | 在官方前端代码或公开资料中找到接口线索 | 仅证明存在候选，不代表当前环境可用 |
| `observed` | 官方网页在已记录环境中实际发出请求 | 证明请求形态被观察，不代表响应或副作用正确 |
| `read-verified` | 已取得成功的脱敏只读响应并核对字段 | 可以用于该环境的只读适配 |
| `behavior-verified` | 在专用环境完成写入、重复提交保护和最终状态复查 | 可以形成该版本的写操作兼容结论 |
| `failed` | 已复现不可用、权限不足或契约不兼容 | 必须记录错误语义和降级行为 |

证据等级不得由推测提升，也不得用其他 DSM build、其他套件版本或其他权限账号的结果替代。

## 升级复验

DSM 或相关套件升级后：

1. 保留旧环境记录，新建环境快照，不覆盖旧版本。
2. 复制 [`upgrade-reports/TEMPLATE.md`](upgrade-reports/TEMPLATE.md)。
3. 重新执行 `SYNO.API.Info` 与关键只读契约检查。
4. 对比 API 名称、路径、版本、必需参数、响应容器、字段类型、错误码和权限。
5. 先验证降级路径，再决定是否启用内部能力。
6. 内部写能力在新版本完成行为验证前保持关闭。
7. 同步更新端点记录、机器可读索引、产品兼容矩阵、相关 Adapter 和自动化测试。

旧版本记录只能追加更正说明，不直接改写历史观察。若历史结论错误，应说明更正日期、原因和受影响版本。

## 命名

- 环境：`YYYY-MM-DD-dsm-<build>-<用途>.md`
- 端点：`<所属范围>-<稳定能力名>.md`
- 升级报告：`YYYY-MM-DD-<旧版本>-to-<新版本>.md`
- 脱敏 fixture：`<端点标识>-<环境标识>-<场景>.json`

文件名只使用小写字母、数字和连字符，不包含设备名、主机名、账号或套件中的用户数据。
